原有70项包括34项MySQL HTTP用例和36项SQL Server/PostgreSQL服务层用例，ID集合与首轮一致。新增31项用于验证缺陷修复及稳定性、并发、权限和边界场景；循环请求次数和并发执行轮次均按一个测试场景统计，没有重复计入用例数量。

## 执行与判定方法

真实启动Flask线程服务，向MySQL、SQL Server和PostgreSQL三套隔离测试库写入合成数据。以HTTP响应、角色提示、记录条数、库存变化和数据库前后快照综合判断结果。修复前的响应和日志使用保留的首轮记录，修复后逐条保留预期结果、实际状态和数据快照。

图书实际顺序为34项HTTP回归（含原失败场景）、36项服务回归，再31项专项；不是先独立完成全部缺陷复测再执行70项。服务在本轮HTTP和专项之间未重启。

## 结论

图书独立修复版本在本轮界定的登录、图书、读者、借还、库存、权限及逾期查询范围内，101项全部通过，6条已确认缺陷修复通过，负库存待确认项按测试副本规则落实。本轮核心业务回归达到约定用例范围的通过条件；原项目仍是未修复版本，不能把此结论应用于原部署。

## 未测试与限制

- 图书同步、邮件、报表仍关闭、未测试；不是整个系统验收。
- 并发规模为双线程；90请求不等于长时或高负载性能测试；29/31天场景不证明精确到秒的30天边界。
- SQL Server/PostgreSQL以服务层验证，不写成三库全量浏览器测试。
- 原有MD5密码、固定密钥、GET写操作及CSRF等安全加固不属于本轮；尚未完成全面安全评估。
