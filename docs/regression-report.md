## 执行与判定方法

测试在独立修复副本和三套隔离测试库中进行，不修改原项目和原数据库。

测试时真实启动Flask服务，向MySQL、SQL Server和PostgreSQL隔离测试库写入合成数据，通过以下证据综合判断结果：

- HTTP状态码和页面提示；
- 不同角色的访问与操作结果；
- 图书、读者和借阅记录条数；
- 借阅、归还前后的库存变化；
- 三套数据库执行前后的数据快照；
- 服务日志及异常信息。

修复前的响应、日志和失败结果使用保留的首轮记录；修复后重新执行对应失败用例，并开展核心功能和新增专项回归。

本轮实际执行顺序为34项HTTP回归、36项服务层回归和31项新增专项测试。

## 缺陷修复与复测

本轮在独立副本中完成以下问题的修复和验证：

1. 修复库存为1时，两个并发请求生成两条借阅记录的超借问题；
2. 修复非数字库存参数触发HTTP 500的问题；
3. 修复借阅参数缺失触发HTTP 500的问题；
4. 修复请求结束后数据库会话未及时释放导致的连接池耗尽问题；
5. 修复根据逾期标志查询造成的实际逾期记录漏查问题；
6. 落实负库存输入校验规则，拒绝保存小于0的库存。

修复后重新执行对应失败场景，并完成登录、图书、读者、借阅、归还、库存、权限和逾期查询回归，相关用例全部通过。

## 测试结论

独立修复版本在本轮界定的登录、图书管理、读者管理、借阅、归还、库存、角色权限和逾期查询范围内，共执行101项用例，101项全部通过。

6项已确认问题均完成修复和复测，核心业务达到本轮约定用例范围的通过条件。

该结论仅适用于独立修复版本。原项目仍保留原始状态，不能将本轮通过结论直接应用于原项目或其他部署环境。

## 未测试范围与限制

- 多数据库同步、邮件提醒和报表模块未纳入本轮测试；
- 并发测试规模为双线程，不代表高并发或长时间压力测试；
- 连续90次请求用于检查基本稳定性，不等同于完整性能测试；
- SQL Server和PostgreSQL主要通过服务层及数据库快照验证，未执行三套数据库的完整浏览器端重复测试；
- 29天和31天逾期场景用于验证日期边界，不代表已经完成精确到秒的30天临界测试；
- MD5密码、固定密钥、GET写操作、CSRF等安全问题未纳入本轮修复范围；
- 本轮结论不能代表整个系统已经完成全面安全测试和性能测试。
